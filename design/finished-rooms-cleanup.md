# 끝난 방 정리 (설계서, 2026-11-20 — 승인 전)

## 1. 한 줄 요약
끝난 지 7일 넘은 대결 방(가격·거래·주문·증강 줄 등)을 지워 DB가 계속 커지지 않게 해요. 전적·업적·경험치·랭킹은 그대로 남아요. 플레이어 화면에서 달라지는 것은 없어요.

## 2. 지금 왜 못 지우나
- 판 결과 `match_history.room_id` 는 방이 지워지면 비워져요(`on delete set null`).
- 그런데 전적(`history`)·업적(`earnedBadges`)·손님 기록 가져오기(`mergeGuest`)는 **`players` 줄(user_id → room_id)** 로 내 판을 찾고, 그 room_id 로 결과를 이어요. 방을 지우면 `players` 줄도 함께 지워져(cascade) 전적과 업적이 사라져요.

## 3. 바꾸는 것
| 단계 | 내용 |
|---|---|
| ① 새 표 `history_seats` | (history_id → match_history.id cascade, user_id → auth.users cascade, nickname, created_at), 기본키 (history_id, user_id). 서버 비밀 키만 읽고 씀(RLS·권한 회수) |
| ② 채우기 | `match_history` 가 생길 때 그 방의 `players`(user_id 있는 자리)를 그대로 옮겨 적음 — DB 트리거(코드 여러 곳에서 결과를 만들어도 빠짐없이). 지금까지의 판은 한 번에 옮겨 적음(여러 번 실행해도 안전) |
| ③ 읽는 곳 바꾸기 | `history`·`earnedBadges` 는 `history_seats` 로 내 판을 찾음(없으면 예전 방식 — 마이그레이션 전에도 안 죽게). `mergeGuest` 는 손님 → 회원으로 `history_seats.user_id` 도 옮김 |
| ④ 지우기 | `cleanup_stale()` 에 "끝난 지 7일 넘은 방 삭제" 추가 (진행 중·대기 방은 지금 규칙 그대로) |

- `match_players`(점수 기록)·`game_stats`(판 기록)·`xp_log`·`daily_runs`·`play_days` 는 방이 지워져도 남게 이미 되어 있음 (방 번호만 남거나 비워짐)
- 7일: 결과 화면을 다시 열거나(`/game/코드` 새로 고침) 한 판 더를 누를 여유

## 4. 화면 데이터 / 보안
- 새로 화면에 보내는 값 없음. `history_seats` 는 서버만 (계정 id 를 화면에 안 보냄 — 지금과 같음)
- 지운 방의 시드·salt 도 함께 사라짐 → 지난 판 시장을 다시 만들 수 없음 (결과·전적은 남음)

## 5. 진행 중인 게임: 영향 없음 (끝난 지 7일 넘은 방만)

## 6. 악용·위험
- 잘못 지우기: 삭제 조건은 `status = 'finished'` + 마지막 갱신 7일 전, 한 번에 최대 500개 · 적용 전 지울 개수를 먼저 세어 보고
- 전적 사라짐: ③을 먼저 배포·확인한 뒤에 ④를 켬 (순서 지키기)

## 7. 완료 기준
- [ ] 방을 지운 뒤에도 그 판이 전적·업적 개수·업적 화면에 그대로 (e2e: 시험 판을 끝내고 방만 지운 뒤 history·profile 비교)
- [ ] 손님 기록 가져오기 뒤 가져온 판의 전적이 회원 쪽에 보임
- [ ] 진행 중·대기 방은 안 지워짐 (단위 시험 + 지울 개수 미리 세기)
- [ ] 마이그레이션 전 서버도 전적이 그대로 (예전 방식으로 내려감)

## 8. 언제
DB 약 24MB(무료 500MB) — 급하지 않음. 정식 출시 뒤 이용자가 늘 때, 또는 400MB 가까이 되면 진행.
