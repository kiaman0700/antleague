## A. 연속 기록 2판 (얼리기 없음, 인정되는 판을 해야 이어짐)

**한 줄 요약**: '연속 n일'은 들어온 날이 아니라 **인정되는 판을 1판 이상 제대로 한 날**만 셈. 얼리기 없음.

| 항목 | 값 (기본값 — 바꾸려면 말씀해 주세요) |
|---|---|
| 인정 판 | 랭킹전 · 일반전 · 오늘의 도전 |
| 빼는 판 | 봇전 · 커스텀 · 친구 1대1 · 연습 · 튜토리얼 (혼자·아는 사람끼리 쉽게 채울 수 있음) |
| '제대로 한 판' | 끝까지 함(기권 X) + 거래 1번 이상 (지금 미션·판 경험치 기준과 같음) |
| 날 기준 | 한국 0시. 판이 **끝난** 날로 셈 |
| 끊기면 | 0부터. 얼리기 없음. '최고 n일'은 남김 |
| 표시 | 마이프로필·위 메뉴 프로필 팝업 '연속 n일 · 최고 n일', 결과 화면 '오늘 인정 ✓ (연속 n일)', 로비에 오늘 아직이면 '오늘 한 판 하면 n일째' 한 줄 |
| 기념 | 7·30·100일 표시만 (보상 없음 — 기본값) |
| 대상 | 회원·손님 모두 (손님은 자동 삭제되면 같이 사라짐) |

근거: 듀오링고·NYT 워들은 '그날 실제로 한 것'만 셈, NYT 는 얼리기 없음. 브롤스타즈는 봇전을 연승에서 뺌(쉬운 판 채우기 막기). 끊긴 뒤 '최고 기록'을 함께 보여 주면 덜 아픔.

**서버만**: 판이 끝날 때(`maybeAdvance` → 미션 판정 자리) 조건을 확인해 `play_days(계정, 날짜)` 에 한 줄(기본키로 한 번만). 화면은 계산된 숫자(연속·최고·오늘 했는지)만 받음.
**DB**: `060_play_days.sql` — play_days 표(서버 전용). 지금 오늘의 도전 기록(daily_runs 끝낸 날)은 옮겨 넣어 기존 연속이 끊기지 않게.
**없애는 것**: 오늘의 도전 연속의 얼리기(streak.ts freeze), 오늘의 도전 친구 '함께 n일'.

완료 기준
- [ ] 봇전·커스텀만 한 날은 이어지지 않는다 (단위)
- [ ] 기권·거래 0회 판은 인정 안 됨 (단위·e2e)
- [ ] 하루 빠지면 0, 최고 기록은 남음 (단위)
- [ ] 다른 사람의 연속 기록은 화면 데이터에 없음 (정보 안 샘)

## B. 오늘의 도전 '오늘의 시장'

**한 줄 요약**: 오늘의 도전마다 그날의 시장 이름이 붙고(예: '테마주 광풍'), 그 사건이 판 안에 꼭 하나 나옴. 어느 종목·몇 일차인지는 비밀.

| 테마 (7개, 날마다 돌림 — 이틀 연속 같은 것 없음) | 꼭 나오는 사건 |
|---|---|
| 테마주 광풍 | 소문으로 상한가 2~4일 → 투자경고 → '사실무근' 하한가 |
| 전쟁과 유가 | 가상 지역 분쟁: 유가↑·항공↓·정유↑, 다음 날 일부 회복 |
| 상장 폐지 주의보 | 소문 → 공시 → 거래정지 → 정리매매 (15%는 개선기간 뒤 재개) |
| 금리 충격 | 연준·금통위 날 금리 0.5%p 깜짝 변경 |
| 신약 승인 발표 | 미국 승인 결과 날 큰 등락 |
| 공매도 보고서 | 공매도 보고서 급락 (30%는 오보) |
| 유상증자 | 유상증자 공시 급락 |

- 고르는 법: 서버 비밀 키 HMAC('daily-theme:'+날짜) 로 고르고 전날과 같으면 다음 것.
- 공개: 그날 0시부터 테마 이름 + 한 줄 설명 (모두 같은 시장이라 공정). 다음 날 테마는 미리 안 보임.
- 화면: 연습 메뉴 '오늘의 도전' 칸·시작 창·결과 화면에 '오늘의 시장 · 테마주 광풍'. 결과 '실제 시장에서는?'이 그 사건 설명을 먼저.
- 기록: 테마별 내 최고 기록(기본값: 이번엔 표시만 하지 않고 다음에).

**규칙 버전 v26** = v25 + (테마가 있는 판만) 사건 강제(전용 난수 `ev26`). 테마 없는 v26 판은 v25 와 가격이 같음(지문 테스트). 오늘의 도전만 테마를 씀 — 랭킹전·일반전·봇전은 그대로.
**서버만**: 사건 종목·날짜·결과. **화면**: 테마 이름·설명(공개), 나머지는 지금처럼 그날까지 공개된 뉴스만.

완료 기준
- [ ] 7개 테마 각각 여러 시드에서 그 사건 뉴스가 반드시 나온다 (단위)
- [ ] 테마 없는 v26 = v25 가격 (지문)
- [ ] 화면 데이터에 사건 종목·날짜가 미리 없음 (정보 안 샘)
- [ ] 이틀 연속 같은 테마 없음 (단위)
- [ ] 봇 시뮬 난이도별 결과가 크게 안 바뀜

## C. 손님 닉네임을 회원이 쓸 수 있게

**한 줄 요약**: 회원 가입·닉네임 바꾸기 때 손님이 쓰던 닉네임도 고를 수 있음(지금도 가입은 됨). 그 손님은 다음에 게임을 시작할 때 서버가 겹치지 않는 무작위 닉네임으로 바꾸고 한 번 알려 줌.

| 항목 | 값 |
|---|---|
| 무작위 이름 | '형용사 + 개미 + 숫자 4자리' (예: 신중한개미4821) — 10자 안, 회원 닉네임과 안 겹치게 서버가 확인 |
| 바뀌는 때 | 손님이 다음에 방 만들기·입장·대결 찾기·봇전을 할 때 (지금은 '닉네임을 바꿔 주세요' 오류) |
| 진행 중인 판 | 그 판 이름은 끝날 때까지 그대로 |
| 알림 | 바뀐 뒤 한 번 창: "회원이 '○○' 닉네임을 등록해서 손님 닉네임이 '신중한개미4821'로 바뀌었어요. [닉네임 바꾸기] [확인]" |
| 미리 고지 | 시작 창 비교표 '닉네임' 칸, 설정 '내 계정', 이용약관 제3조에 "손님 닉네임은 회원이 같은 이름을 등록하면 자동으로 바뀌어요" |
| 회원 쪽 | 가입 화면에 '손님이 쓰던 이름'이라고 알리지 않음 (누가 쓰는지 드러나지 않게) |

근거: 라이엇·디스코드는 이름이 걸리면 다음 접속 때 창으로 알리고 무료로 바꾸게 함. 배틀넷은 임시 이름을 주고 안내. '이유를 모른 채 바뀜'이 가장 큰 불만이라 이유를 꼭 적음.

완료 기준
- [ ] 회원이 손님 닉네임으로 가입 가능 (e2e)
- [ ] 그 손님이 다음에 방에 들어가면 회원과 안 겹치는 '…개미숫자' 이름으로 바뀌고 응답에 바뀐 사실이 옴 (e2e)
- [ ] 진행 중이던 판의 이름은 그대로 (e2e)

## D. 커스텀 방 '빠른 참가'

**한 줄 요약**: 커스텀 메뉴·방 찾기에 '빠른 참가' — 조건에 맞는 열린 방에 바로 들어감. 없으면 "조건에 맞는 방이 없어요"와 함께 같은 조건으로 방 만들기를 권함 (카트라이더·크레이지아케이드의 빠른 입장 느낌, 매칭 아님).

| 항목 | 값 |
|---|---|
| 고르는 조건 | 인원(1대1 / 3명 이상 / 상관없음) · 하루 길이(1분 / 3분 / 5분 이상 / 상관없음) — 기본 '상관없음' |
| 들어갈 수 있는 방 | 대기 중 · 비밀번호 없음 · 자리 남음 · 방장이 사람이고 자리에 있음(90초 안) · 나와 차단 관계인 사람이 없음 |
| 순서 | 사람이 가장 많은 방 먼저(빨리 시작하게), 같으면 오래 기다린 방 |
| 없을 때 | "조건에 맞는 방이 없어요" + [이 조건으로 방 만들기](방 만들기 화면에 조건을 채워 엶) · [조건 바꾸기] |
| 점수 | 없음 (커스텀 그대로) |
| 횟수 제한 | 1분 10번 (서버) |

근거: Photon·Normcore 표준은 '자리 남은 가장 찬 방 먼저, 없으면 방 만들기'. 어몽어스는 맞는 방이 0개면 조건을 바꾸라고 안내. 비밀번호 방은 코드로만.

**서버**: `quickJoin {size, speed}` — 위 조건으로 방을 고르고 기존 입장(join) 과정을 그대로 거침(한 사람 한 방 `ensureFree`, 동시 입장 잠금). 응답은 기존 입장과 같음. 화면 데이터에 다른 방 정보는 안 늘어남.

완료 기준
- [ ] 비밀번호·꽉 찬·시작한 방에는 안 들어감 (e2e)
- [ ] 조건에 맞는 방이 없으면 404 + 안내, '방 만들기'를 누르면 조건이 채워져 있음 (e2e·화면)
- [ ] 차단한 사람이 있는 방에는 안 들어감 (e2e)

## 바로 하는 것 (설계서 없이 — 지시가 분명함)
- 봇전 경험치: 하루 **첫 판만** (이기면 +5·어려움 봇 +10 그대로, 그다음 판은 0) — 결과 화면 '오늘 봇전 경험치는 받았어요'
- 반응 끄기를 켜면 내 반응 보내기도 막음
- 오늘의 도전 친구 '함께 n일' 없앰
- 동시 접속 (FC온라인 방식 — 사용자 지시 2026-11-19): 로그인은 여러 기기 허용. 다른 기기가 **지금 접속 중(90초 안에 화면을 보며 씀)**이면 로그인할 때(또는 쉬던 기기를 다시 쓰기 시작할 때) 먼저 묻기:
  - 창: "다른 기기에서 접속 중이에요. 여기서 접속하면 그 기기는 동시 접속으로 로그아웃돼요. 여기서 접속할까요?" [여기서 접속] [취소]
  - [여기서 접속] → 다른 기기는 로그아웃, 그 기기 화면: "다른 기기에서 접속해서 동시 접속으로 로그아웃됐어요. 본인이 아니라면 비밀번호를 바꿔 주세요."
  - [취소] → 이 기기는 접속하지 않음(방금 한 로그인이면 로그아웃, 쉬던 기기면 로그아웃)
  - 다른 기기가 쉬는 중(90초 넘게 안 씀·창을 닫음)이면 묻지 않고 그냥 로그인, 쉬던 기기도 로그아웃되지 않음
  - 창이 뒤에 숨은 기기의 요청은 '접속 중'으로 치지 않음, 창을 닫으면 바로 '안 쓰는 중'
  - 게스트 코드로 불러오기·비밀번호 바꾸기는 지금처럼 다른 기기를 끊음
  - 서버: 묻지 않고 넘어가는 길 없음 — 확인 전 요청은 409 `concurrent`(행동 안 함), `takeOver` 로만 바꿈. DB `061_concurrent_sessions.sql`
  - 근거: 사용자가 든 FC온라인 규칙(공식 문구는 인터넷에서 못 찾음). 스팀도 '다른 PC에서 게임 중 — 여기서 하면 그쪽이 끊김'을 묻고 고르게 함
