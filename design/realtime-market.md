# 실시간 장중 시장 — 기능 설계서

> 상태: **구현 완료** (2026-11-15)
>
> 설계와 달라진 점
> - DB 006 마이그레이션 불필요: 장 시작 = `day_deadline - 제한 시간` 으로 계산
> - 마감 때 '남은 장중 흐름 빠르게 재생'은 하지 않음 — 마감하면 결산 화면에서 종가 확정 (추후 개선 후보)
> - 혼자 연습은 장 마감을 누르거나 시간이 끝나면 바로 다음 날 장이 시작됨 (결산 화면을 보는 동안에도 시간이 흐름)

## 1. 한 줄 요약

하루(턴) 동안 **가격이 시간에 따라 실제로 움직이고, 장중에 속보가 뜨고**, 예약 매수·매도는 **가격이 닿는 순간** 체결된다. 지금은 하루 내내 시가로만 거래하고 마감 때 한꺼번에 움직인다.

## 2. 규칙

| 항목 | 내용 |
|---|---|
| 장중 시간 | 하루 제한 시간(1·3·5·10분) = 장이 열려 있는 시간 |
| 가격 갱신 | **5초마다 한 칸** (1분 방 12칸, 3분 36칸, 5분 60칸, 10분 120칸) |
| 거래 가격 | 주문을 누른 **그 순간의 현재가** (서버 시각 기준). 체결가는 알림으로 보여 줌 |
| 예약 주문 | 넣은 **뒤에** 가격이 닿으면 그 칸에서 바로 체결 (지금은 마감 때 한꺼번에 처리) |
| 장 마감 | 모두 마감·카운트다운 끝·시간 끝 → 남은 장중 흐름이 **빠르게 재생**되고 종가 확정 (지금의 마감 애니메이션 활용) |
| 아침 뉴스 | 장 시작 때 공개 (지금처럼) |
| 장중 속보 | 하루 0~2개. 장 중간(20~80% 지점)에 뜨고, **관련 종목은 속보가 뜬 뒤에** 크게 움직임 |
| 루머 감별기 | 그때까지 뜬 뉴스 전부 판정 + 이후 뜨는 속보도 판정 |
| 1대1 / 3인 이상 | 같음 (카운트다운 규칙은 지금 그대로) |

기본값 (바꾸려면 말씀해 주세요):
- **혼자 연습**: 하루 길이를 1·3·5분 중 고름 (기본 3분). "장 마감"을 누르면 남은 시간을 빠르게 넘김
- 가격 갱신 간격 5초

## 3. 서버가 정하는 것 / 화면에 보내는 것

| 화면에 보냄 | 절대 안 보냄 |
|---|---|
| 지금 칸까지의 장중 가격 | 다음 칸 이후 가격, 오늘 종가 |
| 지금까지 뜬 뉴스·속보 | 아직 안 뜬 속보 (내용·시각 모두) |
| 오늘 장 시작·끝 시각, 지금 칸 번호 | 시드, 가짜 여부(감별기 없이) |
| 내 거래·주문 | 상대 거래·주문·카드 |

- 거래·예약 체결 가격은 **서버가 시각으로 계산**. 화면이 보낸 가격·시각은 무시
- 화면은 2.5초마다 받아 오고(지금처럼), 5초 칸이 바뀌면 차트에 한 칸 추가

## 4. DB 변경 — `supabase/006_realtime.sql`

- `rooms.day_started_at timestamptz` — 오늘 장 시작 시각 (칸 번호 계산용)
- `orders.filled_at_tick integer` — 몇 번째 칸에서 체결됐는지 (기록·표시용)
- 적용 전 방어: `day_started_at` 이 없으면 `day_deadline - 제한시간` 으로 추정

## 5. 진행 중인 게임에 미치는 영향

- **시가·종가·고가·저가는 그대로.** 지금 8칸짜리 장중 흐름 사이를 **다른 난수**로 잘게 이어서(고가·저가 범위 안에서) 5초 칸을 만듦 → 같은 시드의 일별 가격은 바뀌지 않음
- 배포 순간 진행 중인 판은 그날부터 실시간 규칙으로 바뀜 (사람이 적을 때 배포 권장)

## 6. 화면

**모바일 세로**
- 차트 탭: 기본 보기를 **"오늘(장중)"** 선 차트로, 오른쪽 끝 점이 5초마다 이동. 기존 일별 캔들은 탭으로 전환
- 위쪽 줄: 남은 장 시간 막대(진행 바) + 현재가 깜빡임
- 속보가 뜨면 위에서 토스트 + 뉴스 탭 점 표시

**모바일 가로**: 차트 탭은 차트가 화면 대부분을 차지 (지금 줄인 위쪽 줄 유지)

**PC**: 가운데 차트가 장중 보기, 오른쪽 뉴스 칸 맨 위에 속보가 빨간 띠로 들어옴. 종목 목록 가격도 5초마다 갱신

스크롤바가 새로 생기지 않게 (차트 높이는 화면에 맞춤)

## 7. 악용 시나리오

| 시도 | 막는 법 |
|---|---|
| 화면 시각을 바꿔 미래 가격 보기 | 미래 칸은 서버가 안 보냄. 가격은 서버 시각으로만 |
| 체결 직전 가격으로 주문 (지연 이용) | 체결은 서버가 요청을 받은 시각의 칸 가격 |
| 예약 주문을 과거 칸에 체결시키기 | 주문 넣은 칸 **이후**의 칸만 확인 |
| 속보 미리 알아내기 | 안 뜬 속보는 데이터에 없음. 화면 데이터에 "속보 개수"도 안 넣음 |
| 요청 폭주로 서버 부담 | 지금 요청 제한 유지 + 시장 데이터는 칸이 바뀔 때만 다시 보냄 |

## 8. 완료 기준 체크리스트

- [ ] 같은 시드의 일별 시가·종가·고가·저가가 바뀌지 않는다 (단위)
- [ ] 장중 5초 칸 가격은 그날 고가·저가 범위 안이고, 첫 칸 = 시가, 마지막 칸 = 종가 (단위)
- [ ] 화면 데이터에 지금 칸 이후 가격이 없다 (단위, 정보 누출)
- [ ] 화면 데이터에 아직 안 뜬 속보가 없다 (단위, 정보 누출)
- [ ] 거래 가격 = 요청 시각의 칸 가격 (단위 + e2e)
- [ ] 예약 주문은 넣은 뒤에 가격이 닿은 칸에서 체결된다 / 넣기 전 칸은 무시 (단위)
- [ ] 속보 관련 종목의 큰 움직임은 속보 뒤에 일어난다 (단위)
- [ ] 1분 방에서 실제로 차트가 움직이고, 속보가 뜨고, 마감 때 남은 흐름이 재생된다 (브라우저)
- [ ] 혼자 연습도 같은 방식으로 동작한다 (브라우저)
- [ ] 모바일 세로·가로, PC 1366×768 에서 옆 스크롤 없음, 콘솔 에러 0 (브라우저)
- [ ] 기존 e2e 3종 + 새 실시간 e2e 통과

## 작업 순서 (승인 후)

1. 엔진: 5초 칸 가격 생성(별도 난수) + 칸 번호 계산 + 정보 자르기 — 테스트 먼저
2. 엔진: 거래 가격·예약 체결을 칸 기준으로 — 테스트 먼저
3. 장중 속보 — 테스트 먼저
4. DB 006 (내용 보여 드리고 승인 후 적용) + 서버
5. 화면: 장중 차트·남은 시간·속보 (모바일·PC)
6. 혼자 연습
7. `game-self-check` 전체
