# 기기 종류로 화면 고르기 (창 크기 대신)

작성 2026-11-17 · 스킬: game-feature-spec · 상태: **완료** (좁은 PC 창 = 900px 유지 + 가로 스크롤 — 사용자 결정 2026-11-17)

## 1. 한 줄 요약
지금은 **창의 가로 폭**으로 화면을 고름(게임 960px·로비 860px 이하면 휴대폰 화면) → PC에서 창을 줄이면 휴대폰 화면이 나옴.
바꾸면: **기기 종류(PC·태블릿·휴대폰)를 먼저 알아내고** 그 기기용 화면을 고정. 같은 기기 안에서만 창 크기에 맞춰 조금씩 조정.

## 2. 기기를 알아내는 법 (브라우저가 알려 주는 것만, 서버로 보내지 않음)
| 기기 | 판단 기준 (위에서부터 먼저 맞는 것) |
|---|---|
| 직접 고름 | 설정 '화면 종류: 자동/PC/태블릿/휴대폰' 을 고른 경우 그대로 (이 기기에 저장) |
| 휴대폰 | 터치가 주된 입력(`pointer: coarse`) 이고, **화면 자체**(창이 아니라 기기 화면)의 짧은 쪽이 600px 미만 |
| 태블릿 | 터치가 주된 입력이고 화면 짧은 쪽이 600px 이상 (아이패드가 '데스크톱 사이트'로 PC 처럼 보이는 경우: 터치 지점 2개 이상 + Mac 이면 태블릿) |
| PC | 그 밖 (마우스가 주된 입력) — 터치 되는 노트북도 마우스가 주된 입력이면 PC |

- 판단 결과는 페이지 맨 바깥에 `data-device="pc|tablet|phone"` 로 붙이고, 화면 코드·CSS 가 이 값으로 화면을 고름
- 휴대폰·태블릿을 돌리는 것(세로↔가로)은 지금처럼 그때그때 반영

## 3. 기기별 화면
| 기기 | 화면 | 창(화면) 크기에 따른 조정 |
|---|---|---|
| PC | 늘 **PC 화면**(위 메뉴바·오른쪽 소셜 칸·게임은 칸 나눔) | 창이 좁아지면 PC 화면 안에서 좁게: 소셜 칸은 접힘 → 칸 순서를 위아래로. **기본값: 900px 보다 좁으면 그 폭(900)을 유지하고 가로 스크롤** (휴대폰 화면으로 바뀌지 않음) |
| 태블릿 | 세로: 지금의 태블릿 화면(목록+차트 나란히·아래 탭바) · 가로: PC 화면을 터치용으로(버튼 크게) | 기기 안에서만 |
| 휴대폰 | 휴대폰 화면(세로·가로) | 기기 안에서만 |

## 4. 서버·DB·진행 중인 게임
- 서버·DB 변경 없음. 화면 데이터도 그대로. 진행 중인 게임 영향 없음 (화면 고르는 방식만 바뀜)

## 5. 바꿔야 할 곳 (규모)
- 화면 코드에서 '휴대폰인지' 묻는 곳 10곳(`useIsMobile` 등) → 기기 값 + 그 기기 안의 크기로
- CSS 에서 화면 종류를 가르는 폭 규칙 약 20~30곳(`max-width: 860px` / `960px` 등) → `data-device` 로 (기기 안의 세부 조정 폭 규칙은 그대로 둠)
- 큰 작업이라 **한 번에 바꾸고 아래 시험을 모두 통과한 뒤** 배포

## 6. 시험 방법 (휴대폰·태블릿을 PC 에서 어떻게 시험하나)
1. **기기 흉내 내기 시험(자동)**: Playwright 의 기기 흉내(터치·화면 크기·휴대폰 브라우저 정보까지 그대로)로 — 창 크기만 줄이던 지금과 달리 '진짜 휴대폰처럼' 보임
   - 휴대폰: 아이폰 SE(375×667)·아이폰 15(393×852)·갤럭시(360×780) 세로/가로
   - 태블릿: 아이패드(820×1180) 세로/가로·갤럭시 탭(800×1280)
   - PC: 1920·1440·1280·1024·800(좁은 창) — **800에서도 PC 화면인지** 확인
   - 모든 로비 화면 + 게임(뉴스·종목·차트·재산·카드) × 위 기기 → 가로 넘침·가려짐·글자 대비 자동 검사, 화면 사진 저장 (스크립트 `scripts/e2e/devices.mjs` 로 만들어 언제든 다시)
2. **개발용 주소 강제**: `?device=phone|tablet|pc` 를 붙이면 그 창에서만 그 기기 화면으로 (PC 브라우저로 빠르게 확인용, 저장 안 함 — 화면 고르기만 바뀌어서 보안 영향 없음)
3. **설정의 '화면 종류'**: 사용자도 직접 고를 수 있어 이상하게 판단된 기기(접는 폰·터치 노트북)도 해결
4. **실제 기기**: 배포 뒤 사용자 휴대폰·태블릿으로 최종 확인

## 7. 악용·위험
| 위험 | 대응 |
|---|---|
| 기기 판단이 틀림 (접는 폰, 터치 노트북, 아이패드+키보드) | 설정에서 직접 고르기 + 개발용 주소 강제 |
| PC 창을 아주 좁게 하면 PC 화면이 잘림 | 900px 아래는 가로 스크롤 (기본값) |
| 보안 | 기기 판단은 화면에서만, 서버로 안 보냄 · 게임 규칙·정보 공개 범위 변화 없음 |

## 8. 완료 기준
- [ ] PC(마우스)에서 창을 800px 로 줄여도 PC 화면 (기기 흉내 시험)
- [ ] 휴대폰 흉내(375·393·360)에서 휴대폰 화면, 돌리면 가로 휴대폰 화면
- [ ] 태블릿 흉내(아이패드 세로)에서 태블릿 화면, 가로에서 PC 화면(터치용)
- [ ] `?device=phone` 이면 PC 창에서도 휴대폰 화면
- [ ] 설정 '화면 종류'를 바꾸면 바로 바뀌고 새로고침해도 유지
- [ ] 모든 기기 × 모든 화면에서 가로 넘침 0, 글자 대비 기준 통과 (`devices.mjs`)
- [ ] 단위 테스트·빌드·e2e 전체 통과
